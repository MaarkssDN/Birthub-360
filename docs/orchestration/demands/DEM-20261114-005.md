## Objetivo e escopo
Substituir cores hex neon hardcoded (`#00D4FF`, `#FF2D9B`, `#FFC107`, `#8B7DFF`,
`#0D0D0D`, `#F8F9FF` e variantes rgba) por tokens CSS (`var(--*)` / classes de token)
nas telas de maior visibilidade, para que a paleta Strategic Command Center apareça de
fato. Escopo: landing, auth, chrome do app (topbar/sidebar/drawer), dashboard home e
componentes ui/ mais visíveis. NÃO é varredura completa dos 107 arquivos — é a primeira
onda das telas que o usuário vê primeiro.

## Mapeamento semântico (decidido pelo 00)
- `#00D4FF` / `#00d4ff` (ciano-neon, ex-`--brand`) → `var(--orbit-blue)` quando usado como
  acento azul; → `var(--brand)` quando usado como cor de marca/ação primária.
- `#FF2D9B` / `#ff2d9b` (rosa-neon, ex-`--brand-2`) → `var(--pink)` ou `var(--brand-2)`
  (Deep Iris `#7C3AED` é o brand-2 oficial — avaliar por contexto: destaque → pink,
  marca secundária → brand-2).
- `#FFC107` (dourado-neon) → `var(--gold)` / `var(--brand)` (mesmo matiz oficial).
- `#8B7DFF` / `#8b5cf6` (violeta) → `var(--iris)`.
- `#0D0D0D`/`#14141a` (fundos escuros) → `var(--bg)`/`var(--surface)` conforme tema.
- `#F8F9FF`/`#f8f9ff` (branco-azulado) → `var(--bg)`/`var(--surface)`.
- rgba equivalentes → `rgb(var(--…))` ou `color-mix` com o token, conforme o arquivo use.
- Em `.tsx` com classes arbitrárias Tailwind: preferir `text-(--token)`/`bg-(--token)`
  (sintaxe TW4) ou `text-[var(--token)]` se a sintaxe parêntese não for suportada pelo
  projeto — verificar padrão existente antes.
- Em `.css` próprio do componente: trocar literal por `var(--token)`.
- NUNCA trocar por hex da paleta nova direto — sempre token, para propagação futura.
